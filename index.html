Guia de estudos · HTML, CSS e BEM

Tudo o que você precisa para começar um projeto web

Um passo a passo para montar a estrutura, escrever HTML semântico, nomear classes com BEM, criar layouts responsivos e entregar sem erros. Feito a partir dos meus estudos de front-end.

Começar um projeto Abrir o checklist

Como usar este guia

  1. 1 Prepare o terreno Clone, pastas e arquivos de configuração. É igual em todo projeto.
  2. 2 Estude o design Antes de programar, anote as medidas numa tabela.
  3. 3 Escreva o HTML Toda a estrutura e os textos, ainda sem CSS.
  4. 4 CSS, um bloco por vez Comece pela maior tela do design e confira no navegador.
  5. 5 Deixe responsivo Media queries só com o que muda em cada tela.
  6. 6 Confira e entregue Marque o checklist, faça commit, push e publique.

Dica

Não tente fazer tudo de uma vez. Termine um bloco, confira no navegador e só depois passe para o próximo. Use a busca no topo (atalho: tecla /) para achar qualquer assunto.

Seção 01

A estrutura de um projeto

Todo projeto termina com a mesma cara. Conhecer o destino ajuda a não se perder no caminho.

A árvore de pastas

Para que serve cada parte

Pasta / arquivo Para que serve Quem escreve

images/ As imagens usadas na página Você exporta do Figma

Seção 02

Passo a passo para começar

Os 11 passos, na ordem. Os primeiros levam uns 15 minutos e são iguais em todo projeto.

  1. 1

    Clonar o repositório

    Crie o repositório no GitHub (botão New repository), ou use o que já foi criado para você, e traga ele para o computador. No VS Code, abra o terminal em Terminal → New Terminal e entre na pasta onde ficam os seus projetos:

    Depois clone, trocando o seu usuário e o nome do repositório:

    Por fim, abra a pasta no VS Code em File → Open Folder.

    O que o clone faz

    Baixa o repositório e já deixa ele conectado ao GitHub. Assim, depois, o git push sabe para onde enviar.

  2. 2

    Criar as pastas

    Na barra lateral do VS Code, use o ícone de nova pasta e crie:

    • blocks
    • images
    • pages
    • vendor
    • vendor/fonts (só se o projeto pedir fontes locais)

    Atenção ao nome

    Tudo em minúsculas, sem espaços e sem acentos.

  3. 3

    Os arquivos de configuração

    São arquivos de texto. O ponto no começo faz parte do nome. Use o ícone de novo arquivo e digite o nome exatamente assim:

    Arquivo Conteúdo Por quê
    .gitignore .DS_Store O Mac cria esse arquivo oculto sozinho. Ele não deve ir para o GitHub.
    .prettierignore vendor/normalize.css O Prettier formata o código sozinho, mas não deve mexer em código de terceiros.
    .editorconfig Veja em Modelos prontos Faz o editor usar 2 espaços, UTF-8 etc. em qualquer computador.

    Dica de ouro

    Esses três arquivos são iguais em todos os projetos. Copiar do projeto anterior é o normal, não é trapaça.

  4. 4

    O normalize.css

    O normalize "zera" as diferenças entre navegadores (Chrome, Firefox...), para a página ficar igual em todos.

    • Copie de um projeto anterior para vendor/normalize.css, ou
    • baixe do projeto oficial: procure "normalize.css" no GitHub (é gratuito, com licença MIT).

    Regra

    Nunca edite esse arquivo.

  5. 5

    As fontes (se o projeto pedir fontes locais)

    1. Baixe a fonte do site oficial dela, de preferência no formato para web.
    2. No Figma, descubra quais pesos o design usa: clique em cada texto e veja o painel da direita.
    3. Copie só esses pesos, em formato .woff2, para vendor/fonts/. Fontes que não são usadas só deixam o site mais pesado.
    4. Guarde junto o arquivo de licença da fonte (ex.: LICENSE.txt), que vem no download.
    5. Crie vendor/fonts.css com um @font-face para cada peso (veja em Modelos prontos).

    Tabela de pesos (vale decorar):

    Nome no Figma font-weight
    Thin100
    Light300
    Regular / Normal400
    Medium500
    Semi Bold600
    Bold700
    Extra Bold800
    Black900

    E se for Google Fonts?

    Aí não precisa de fonts.css: basta colar no <head> a tag <link> que o Google Fonts fornece.

  6. 6

    O favicon.ico

    O ícone que aparece na aba do navegador. Fica na raiz do projeto.

    • Se o design tiver um ícone, exporte do Figma.
    • Se não tiver, gere um em favicon.io, a partir de uma imagem ou de um texto.
  7. 7

    As imagens

    1. No Figma, selecione a imagem e, no painel direito, vá em Export → Export.
    2. Comprima antes de usar, em squoosh.app ou tinypng.com. Uma foto de 3 MB costuma cair para 200 KB.
    3. Dê nomes consistentes, de preferência o nome da camada no Figma: minúsculas, sem espaços (use - ou _).
    Tipo de imagem Formato
    Fotos .jpg ou .webp
    Logos, ícones, desenhos com cores chapadas .svg
    Imagens com transparência que não são vetor .png
  8. 8

    O pages/index.css

    Ele só tem @import, nesta ordem:

    1. O normalize vem primeiro. No CSS, quando duas regras definem a mesma coisa, vence a que vem depois. Assim os seus estilos sempre ganham do normalize.
    2. O fonts.css vem logo depois. Assim as fontes já estão carregadas quando os blocos forem usá-las.
    3. O @import fica no topo do arquivo. Se vier depois de qualquer regra, o navegador ignora.

    Por que ../?

    O index.css está dentro de pages/. O ../ "volta uma pasta" para a raiz do projeto, e daí entra em vendor/ ou blocks/.

  9. 9

    O index.html

    Comece sempre pelo esqueleto de Modelos prontos. Ele já tem o essencial: as metas, o link do CSS, o favicon e a estrutura div.page com header, main.content e footer. Depois, preencha o conteúdo seguindo a seção HTML e semântica.

  10. 10

    Os arquivos dos blocos

    Conforme você escreve o HTML, cada bloco novo (ex.: class="banner") ganha:

    1. um arquivo blocks/banner.css;
    2. uma linha @import url("../blocks/banner.css"); no pages/index.css.

    Cuidado com o nome do arquivo

    É banner.css: sem ponto no começo e com .css no final. Um erro comum é criar .banner (o nome da classe) e a página ficar sem nenhum estilo.

  11. 11

    O README.md

    Use o modelo de Modelos prontos. Ele precisa ter:

    1. o nome do projeto;
    2. a descrição do projeto e do que ele faz;
    3. as tecnologias e técnicas usadas;
    4. o link do GitHub Pages;
    5. planos de melhoria: ideias para evoluir o projeto.

Seção 03

Lendo o design no Figma

O Figma é onde a designer desenha a página. Tudo está lá, mas você precisa clicar para ver.

Primeiros passos

  • Se pedir login, crie uma conta gratuita.
  • Se o arquivo estiver lotado, baixe o .fig e importe na sua conta: Drafts → Import.
  • Para não se distrair com os cursores de outras pessoas: View → desmarque "Multiplayer cursors".

Como pegar as medidas

Tamanho, fonte e cor de um elemento Clique nele e veja o painel da direita
Distância entre dois elementos Clique em um, segure Alt e passe o mouse sobre o outro
Distância até a borda da seção Clique no elemento, segure Alt e passe o mouse sobre a seção
Os textos Clique duas vezes no texto e copie com Ctrl + C
Uma sugestão de nome para a classe Olhe o nome da camada no painel da esquerda

Os nomes das camadas dão a dica

Muitos designers nomeiam as camadas como os blocos: banner, about, __title, __subtitle... Quando isso acontece, os nomes BEM já estão quase prontos.

Monte uma tabela de medidas antes de programar

Para cada seção, anote as medidas de cada tamanho de tela. Um exemplo, para uma seção banner fictícia:

Título: fonte / linha 64 / 72px48 / 56px32 / 40px

Com a tabela pronta, o CSS fica quase "copiar e colar".

Convertendo a altura de linha

O Figma mostra a altura da linha em pixels. No CSS, use um número decimal:

Margens: use só uma direção

Decida usar sempre margin-top, ou seja, o espaço até o elemento de cima. Assim você nunca fica em dúvida sobre onde está o espaço.

Exceção

Se as instruções do projeto pedirem a margem num elemento ou numa propriedade específica (por exemplo, margin-bottom no título), siga o que foi pedido.

Seção 04

HTML: estrutura e semântica

"Semântica" quer dizer que a tag descreve o que o conteúdo é, não como ele parece. Isso ajuda leitores de tela, o Google e os revisores.

A tag certa para cada coisa

Conteúdo Tag certa Evite
Topo da página (logo, menu) <header> <div class="header">
Menu de navegação <nav> Uma lista de links solta
Conteúdo principal (só um) <main class="content"> Dois <main>
Uma seção com título próprio <section> <div> genérica
Rodapé <footer> <div class="footer">
Título principal da página (só um) <h1> Vários <h1>
Títulos de seção <h2>, depois <h3>... Pular níveis (h1 → h3)
Parágrafo de texto <p> Texto solto dentro de <div>
Lista de itens parecidos (links, cards, vídeos) <ul> + <li> Vários <div>
Citação <blockquote> <p> com aspas
Link <a href="..."> <a> sem href
Botão de formulário <button type="submit"> <div> ou <a> fazendo papel de botão
Rótulo de campo <label for="id"> Texto solto ao lado do campo
Destacar parte de um texto <span class="..."> <b>, <i>
Agrupar só para alinhar <div> <div> sem necessidade

Evite <b>, <i> e <br>

  • Elas descrevem aparência, não significado. Para dar ênfase de verdade, existem <strong> e <em>.
  • Para só mudar o visual: um <span> com classe, e o estilo no CSS.
  • No lugar de <br>: um <span> com display: block;, ou um max-width que faça o texto quebrar no lugar certo.

Hierarquia de títulos

Nunca pule níveis e nunca use um título só porque "a letra é grande". O tamanho se resolve no CSS.

Imagens

  • Todo <img> precisa de alt, no idioma da página.
  • O alt descreve o conteúdo: "Foto de uma xícara de café sobre uma mesa de madeira", não "imagem1".

Links

  • Todo link precisa de href com um valor.
  • Link para uma seção da página: href="#id-da-secao", e a seção precisa de id="id-da-secao". O nome tem que ser idêntico.
  • Link externo: target="_blank" abre numa aba nova.

Formulários

  • O for do <label> tem que ser igual ao id do <input>.
  • Todo campo precisa de name.
  • Use o type certo: text, email, number, datetime-local, checkbox...
  • required torna o campo obrigatório.

Vídeos do YouTube

  • Use o link /embed/, não o watch?v=.
  • Remova frameborder, width e height do código do YouTube. A borda e o tamanho vão no CSS.

As metas essenciais

Toda página deve ter estas metas dentro do <head>. Elas ajudam o navegador, os buscadores e quem compartilha o link:

E também: <html lang="pt-BR">, um <title> e <link rel="icon" href="./favicon.ico" />.

Comentários

Atalho no VS Code: Ctrl + /. Antes de entregar, apague os comentários desnecessários e deixe só os que explicam algo que não é óbvio.

Seção 05

BEM: como dar nomes e organizar arquivos

BEM é uma regra de nomes para as classes. Com ela, só de ler a classe você sabe onde ela fica e em qual arquivo está o estilo.

As três peças

Peça O que é Formato Exemplo
Bloco Um componente independente bloco header, form
Elemento Uma parte do bloco, que não existe fora dele bloco__elemento header__title
Modificador Uma variação de um bloco ou elemento bloco__elemento_chave_valor form__label_type_checkbox
  • Elemento: dois underlines (__).
  • Modificador: um underline (_), no formato _chave_valor.

Regras de nomes

  1. Só letras minúsculas, e hífen para separar palavras: header__title-accent.
  2. Nada de números ou ordem no nome. Evite: card__title-1, card__title-one, card__first-title. Use a mesma classe card__title em todos, e um modificador se algum for diferente.
  3. Elemento de elemento não existe. Mesmo com o HTML aninhado, o nome é sempre bloco__elemento: errado footer__list__item, certo footer__list-item.
  4. O nome diz o que é, não como parece: header__title, não header__big-blue-text.
  5. Todo elemento estilizado tem classe. Não estilize por tag (h1 { }) nem por id (#about { }).

Modificador sempre junto da classe base

E no CSS, o modificador tem só o que é diferente:

Mix: um elemento que também é bloco

Quando um bloco (ex.: form) fica dentro de outro (ex.: contact):

  • form cuida da aparência: largura máxima, cores, espaçamento interno.
  • contact__form cuida da posição dentro da seção: as margens.

Regra da "geometria externa"

Um bloco não define as próprias margens externas: quem define é o elemento do bloco pai. Assim o bloco form pode ser reaproveitado em outro lugar com outras margens.

Seletores

  • No máximo dois seletores aninhados: .form__checkbox:checked está ok.
  • Prefira uma classe só por regra: .banner__title { }.
  • Nunca use !important.

Estrutura de arquivos BEM Flat

Flat quer dizer: um arquivo por bloco, todos direto em blocks/, sem subpastas.

Como saber onde uma regra vai: olhe o nome antes do __. É o nome do bloco e, portanto, o nome do arquivo.

A classe começa com... Vai para
.header, .header__logo blocks/header.css
.form, .form__input, .form__label_type_checkbox blocks/form.css
.contact__form blocks/contact.css (é elemento de contact)
  • Os media queries ficam dentro do arquivo do bloco, no final.
  • Um bloco sem estilos (como o content do <main>) não precisa de arquivo.

Seção 06

CSS: regras de ouro

Doze regras que evitam a maior parte dos problemas e deixam o código fácil de revisar.

1. Coloque o que é comum no .page e deixe herdar

Todos os textos herdam essas propriedades. Nos outros blocos, escreva só o que é diferente.

É herdado Não é herdado
color, font-family, font-size, font-weight, line-height, text-align margin, padding, background, border, width

2. Sempre tenha fontes alternativas

Se a primeira fonte não carregar, o navegador usa a próxima da lista.

3. Zere os estilos padrão do navegador

h1, h2, p, ul e blockquote vêm com margens. Listas vêm com recuo e marcadores. Links vêm azuis e sublinhados.

4. Os atalhos de margin e padding

5. O que evitar

Não faça Faça no lugar
margin negativa Reorganize o padding ou a estrutura
height fixa em textos Deixe a altura crescer com o texto
width fixa em textos max-width
position: absolute para montar o layout Flexbox ou grid. Absolute só para decoração e sobreposições
!important Um seletor mais específico ou a ordem certa
Estilizar por tag ou id Uma classe BEM

6. width ou max-width?

  • width: 500px: sempre 500px. Em tela pequena, vaza.
  • max-width: 500px: até 500px. Em tela pequena, encolhe.

Para textos e contêineres, use quase sempre max-width. A exceção comum é width: 100%, para uma imagem ocupar toda a largura do pai.

7. Flexbox: o básico que resolve 90% dos casos

Quero... Use
Itens lado a ladodisplay: flex
Itens um embaixo do outroflex-direction: column
Um à esquerda, outro à direitajustify-content: space-between
Tudo centralizadojustify-content: center + align-items: center
Empurrar um item para o fimmargin-top: auto (coluna) ou margin-left: auto (linha)
Espaço igual entre os itensgap
Itens descem de linha quando não cabemflex-wrap: wrap

8. position: quando usar

  • position: relative no pai e position: absolute no filho: o filho é posicionado em relação ao pai, com top, right, bottom e left.
  • z-index decide quem fica na frente (maior = mais na frente). Só funciona em elementos com position.
  • overflow: hidden no pai corta o que sair dele, como um círculo decorativo.

9. box-sizing: border-box em campos

Sem isso, o padding e a borda são somados ao tamanho, e o campo fica maior que o design.

10. Imagem de fundo

Na ordem: cor, imagem, posição (center), tamanho (/ cover) e no-repeat. O caminho começa com ../ porque o CSS está em blocks/.

11. Estados de interação

12. Copie do Figma só fontes e cores

As únicas coisas que você copia igualzinho do Figma são tamanhos de fonte, pesos e cores. Posições e espaçamentos você constrói com flexbox, margin e padding. O Figma costuma sugerir position: absolute para tudo: ignore.

Seção 07

Responsividade (media queries)

Fazer a página funcionar bem do celular de 320px até telas grandes.

A estratégia: desktop primeiro

  1. Escreva tudo para a maior tela do design (ex.: 1280px), sem media query.
  2. Teste. Não pode haver rolagem horizontal.
  3. Adicione @media (max-width: 1024px) com só o que muda no tablet.
  4. Adicione @media (max-width: 544px) com só o que muda no celular.

Como o max-width funciona no media query

@media (max-width: 1024px) quer dizer "aplique quando a tela tiver até 1024px". Numa tela de 320px, os dois media queries valem. Como o de 544 vem depois, ele vence quando os dois definem a mesma propriedade. Por isso:

  • o celular herda tudo o que foi definido para o tablet;
  • você não repete no celular o que já está no tablet. Estilo duplicado entre media queries é código a mais para manter.

Escolhendo os pontos de interrupção

Se ninguém definir os pontos para você, use o meio entre os tamanhos do design:

A ordem dentro do arquivo do bloco

A ordem importa: do maior para o menor.

Como testar

  1. Abra a página no Chrome e aperte F12 (DevTools).
  2. Aperte Ctrl + Shift + M (modo dispositivo).
  3. No topo, escolha Responsive e digite a largura.
  4. Teste as larguras do design (ex.: 1280, 768, 320) e larguras no meio do caminho (ex.: 400, 600, 900, 1150, 1440).
  5. Em cada uma, procure: barra de rolagem horizontal, texto vazando do bloco e elementos sobrepostos.
  6. Teste também no Firefox.

Quanto pode diferir do design?

Diferenças de poucos pixels são normais, porque navegador e Figma desenham o texto de jeitos um pouco diferentes. Se um espaçamento ou tamanho passar de uns 10px de diferença, vale revisar.

Seção 08

Git e GitHub Pages

Salvar o trabalho, enviar para o GitHub e publicar o site.

O ciclo de trabalho

git status mostra o que mudou:

git add . prepara todas as mudanças para o commit:

git commit salva as mudanças no histórico, com uma descrição:

git push envia para o GitHub:

O commit fica só no seu computador até o push

Já aconteceu de o projeto estar commitado mas não enviado, e o GitHub Pages mostrar a versão antiga. Depois do push, confira se os arquivos aparecem no GitHub.

Boas mensagens de commit são curtas e dizem o que foi feito: "Adiciona formulário de contato", "Corrige espaçamento do rodapé". Evite "ajustes" ou "update".

O primeiro push num computador

Na primeira vez, abre uma janela de login do GitHub. Escolha "Sign in with your browser" e autorize. O Windows guarda o acesso para os próximos.

Ativando o GitHub Pages

  1. No GitHub, abra o repositório e vá em Settings → Pages.
  2. Em Branch, escolha main e / (root), e clique em Save.
  3. Em 1 a 2 minutos, o site fica em https://SEU_USUARIO.github.io/NOME_DO_REPOSITORIO/.
  4. Coloque esse link no README.

Depois de cada push, o site se atualiza sozinho em alguns minutos. Se aparecer a versão antiga, recarregue com Ctrl + F5.

Seção 10

Erros comuns (e como resolver)

Clique num sintoma para ver a causa e a solução.

A página aparece sem nenhum estilo

Causa

Os arquivos dos blocos foram criados com o nome da classe (.page) em vez do nome do arquivo (page.css).

Solução

Renomeie com F2: sem ponto no início e com .css no final.

Um bloco ficou sem estilo

Causa

Falta o @import dele no index.css, ou o caminho está errado.

Solução

Confira a linha no pages/index.css e se o caminho começa com ../blocks/.

Um fundo aparece cortado no lugar errado, ou o espaçamento fica em dobro

Causa

Uma <section> dentro de outra com a mesma classe: as duas recebem o mesmo padding e o mesmo fundo.

Solução

Apague a tag duplicada e o fechamento dela.

O ícone da aba não aparece

Causa

rel="favicon", que não existe.

Solução

Use rel="icon".

Clico num link do menu e a página não vai para a seção

Causa

Um link como href="#contact" não tem destino: nenhum elemento tem id="contact".

Solução

Acrescente o id na seção correspondente, escrito exatamente igual ao que vem depois do #.

Aparece uma rolagem horizontal no celular

Causa

Algum elemento é mais largo que a tela, quase sempre por causa de um width fixo em pixels.

Solução

No DevTools, passe o mouse pelos elementos até achar o que passa da borda. Troque o width por max-width, ou use width: 100%.

A imagem fica esticada ou achatada

Causa

A largura e a altura foram fixadas numa proporção diferente da imagem original.

Solução

Use width: 100%, aspect-ratio com a proporção do design e object-fit: cover.

Escrevi um estilo, mas ele não é aplicado

Causa

Outra regra está vencendo: ela vem depois no CSS, é mais específica, ou o nome da classe está digitado diferente no HTML.

Solução

No DevTools, aba Styles: a regra que perdeu aparece riscada, e dá para ver qual venceu. Confira também a grafia da classe nos dois arquivos.

A margem de um bloco muda em todo lugar onde ele aparece

Causa

A margem externa foi colocada no próprio bloco (ex.: .form).

Solução

Use um mix: class="contact__form form", com a margem em .contact__form.

Ajuste o max-width do texto. Nada de <br>.

Seção 12

Glossário

Os termos técnicos do guia, explicados em uma linha.

Bloco (BEM)
Componente independente da página, como header ou form.
Elemento (BEM)
Parte de um bloco: bloco__elemento.
Modificador (BEM)
Variação de um bloco ou elemento: bloco__elemento_chave_valor.
Mix
Um elemento HTML com classes de dois blocos: contact__form form.
BEM Flat
Um arquivo CSS por bloco, todos direto em blocks/.
Semântica
Usar a tag que descreve o conteúdo: <nav>, <footer>...
Herança
Os filhos recebem algumas propriedades do pai, como cor e fonte.
Cascata
Quando duas regras conflitam, vence a mais específica ou a que vem depois.
Breakpoint
A largura em que o layout muda, como 1024px.
Media query
O @media (...) que aplica estilos só em certas larguras.
Viewport
A área visível do navegador.
vh e vw
1% da altura e da largura da viewport: 100vh é a tela inteira.
Flexbox
Sistema de layout para alinhar itens em linha ou em coluna.
Grid
Sistema de layout em linhas e colunas.
fr
Uma fração do espaço livre num grid.
Normalize.css
Arquivo que padroniza os estilos entre navegadores.
@font-face
Regra que conecta um arquivo de fonte ao CSS.
.woff2
Formato de fonte para a web, leve e comprimido.
Favicon
O ícone da aba do navegador.
Clone
Baixar um repositório do GitHub para o computador.
Commit
Salvar um conjunto de mudanças no histórico do Git.
Push
Enviar os commits para o GitHub.
GitHub Pages
Serviço do GitHub que publica o site a partir do repositório.
Validador W3C
Ferramenta que aponta erros no HTML, em validator.w3.org.
DevTools
As ferramentas de desenvolvedor do navegador, abertas com F12.
